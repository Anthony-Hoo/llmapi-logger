# PostgreSQL 与历史存储改造方案

## 目标和不变量

运行时存储改用 PostgreSQL。SQLite 仅保留为只读离线迁移源和兼容性测试，不自动转换、删除或改写旧数据库。四阶段字节计数、hash、完整性链、加密边界、作用域隔离、保留清理及 verified reconstruction 语义不变。后台分析失败不得改变代理响应。

## 设计

1. 将领域 DTO 和通用验证契约从 SQLite 命名空间分离。业务依赖窄接口；数据库实现各自处理 SQL 与事务。
2. PostgreSQL 使用独立版本化 schema、BIGINT 纳秒/计数、BYTEA 密文和指纹、明确外键及索引、identity 分配规则 ID。参数绑定、冲突处理、约束、事务失败和序列语义逐项验证，不运行时替换 SQLite SQL。
3. 保留有界单 writer 队列及确定提交后发布快照。数据库 advisory lock 保证同一数据库仅一个代理写者；锁连接丢失后拒绝继续写入，避免完整性链出现多头。迁移在独立锁和事务内执行。
4. 历史内容先 canonical/hash，再查询已存在对象，仅对新对象压缩加密。必须验证对象身份，不能把 hash 冲突或不同编码静默接受。gzip writer 复用不得跨请求泄漏正文。
5. 重建采用迭代遍历，避免祖先数组逐级复制；保留内容顺序、分支和重建 hash。本轮不额外持久化周期性全量 checkpoint，以免重新引入重复存储；逐祖先完整性验证的 CPU 仍随历史长度增长。
6. insights 保存版本化紧凑派生 detail，不重复持久化整段历史正文/重复数组。读取兼容旧版数据；不能仅压缩后宣称消除二次增长。需要的详情从既有 verified conversation 派生。
7. capture 缓冲按需增长，flush 和阶段终结释放大 backing array。文档明确未提交缓冲在进程崩溃时不能保证持久化，不能虚假承诺 flush。
8. 提供显式离线导入 CLI：源需停写且已备份；只读 SQLite，检查 schema/完整性；目标必须为空；单事务导入并校验逐表行数、密文字节、对象引用、重建/证据摘要及 identity high-water。失败回滚目标，源不变。提供 dry-run。不得打印 DSN、密码、密钥或正文。

## 提交拆分

1. 设计和数据库中立契约。
2. capture 缓冲、gzip 分配及耐久性文档。
3. 内容对象去重与迭代/有界图重建。
4. insights 紧凑派生存储和兼容读取。
5. PostgreSQL schema、事务实现与真实数据库回归。
6. 离线导入和迁移校验。
7. PostgreSQL 默认运行配置、Compose、CI、部署及回滚指南。
8. 端到端、增长回归和最终集成。

实现允许将独立可验证改动进一步拆小，不将不相关改动混入同一提交。

## 验证与回滚

- 真实 PostgreSQL：初始化、重复启动、第二实例拒绝、CRUD、取消/超时、重启、不可用恢复、retention、查询筛选/隔离、协议正常/流式/本地阻断路径。
- 导入：源只读和未变化、空目标要求、失败事务回滚、ID 单调、计数/引用/密文/完整性一致；不接触生产数据。
- 存储增长：逐步增长历史及重复大请求，记录对象行数、detail bytes、分配和 GC；比较基线，不能把可复用空页等同泄漏。
- 全量 Go 测试、race、vet、前端测试和构建；CI PostgreSQL 服务实际执行存储测试。
- 切换前保留 SQLite 与匹配密钥备份。回滚到 v0.6.0 时恢复原配置与备份；切换后 PostgreSQL 中的新写入不会自动回灌 SQLite，回滚前必须明确处理该数据差异。

不包括 PostgreSQL 高可用、横向多代理写入或生产部署。
